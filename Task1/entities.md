# Каталог ключевых сущностей

Предлагаются 15 сущностей. Источники ниже — системы из кейса, где объект ожидаемо создаётся/используется; точные таблицы, API и поля предстоит подтвердить при discovery. Проблемы качества, кроме общей разрозненности из E01, являются проверяемыми гипотезами, а не результатом профилирования production.

| ID / сущность | Описание и основные атрибуты | Связи | Источники / использование As-Is | Критерий включения | Проблемы качества для проверки |
|---|---|---|---|---|---|
| E01 Клиент / Party | Физическое или юридическое лицо: customer_id, party_type, ФИО/наименование, дата рождения/регистрации, идентификационные документы, ИНН, контакты, KYC status | E02, E06 через E14, E11, E13 | FU/RB CRM, клиентские записи Core/Loans | Единый профиль и различение лиц/организаций | Межбанковские дубли, разные IDs/форматы; риск однофамильцев, общих телефонов, старых документов |
| E02 Соответствие идентификаторов | source_system, source_customer_id, customer_id, valid_from/to, recorded_at, match_rule, evidence_ref, decision_status/version | E01 | IDs FU/RB CRM/Core/Cards/Loans; новый Hub ведёт crosswalk | Сохранение ссылок, объяснимый merge/unmerge | Коллизия локальных IDs, повторное использование ID, конфликт сопоставлений |
| E03 Счёт | account_id, source key, legal_entity_id, account_type, currency, status, opened/closed_at, agreement_id | E06, E04, E05, E08, E09 | FU/RB Core; Cards/Loans используют ссылки | Остатки, договорное владение и учёт | Разные статусы/номера, валюта, закрытый счёт как активный, несходящиеся остатки |
| E04 Карта | card_id, processing_id, token/last4, status, expiry, account_id, product_version, holder_ref | E03, E10, E01 через holder_ref | FU/RB Cards, CRM/Core — потребители | Отдельный жизненный цикл инструмента; карта не счёт | Перевыпуск как новая/старая карта, разные статусы, PAN в выгрузках |
| E05 Кредит | loan_id, agreement_id, repayment_account_id, amount, currency, outstanding_principal, schedule_version, status | E06, E03 | FU/RB Loans, Core учёт, CRM/DWH | Долг и договорные условия нельзя мастерить в CRM | Разные определения задолженности/просрочки, версии графика, несходящиеся субрегистры |
| E06 Договор | agreement_id, legal_entity_id, product_id/version, signed_at, effective_from/to, terms_version, status, document_ref | E14, E03, E05, E10 | FU/RB Core, Loans; CRM оформляет/использует | Юридические отношения, продукт и условия на дату | Подмена исторического тарифа текущим, пропуск участника/документа |
| E07 Учётная транзакция | transaction_id, source_system, book/legal_entity, business_date, posted_at, status, reversal_of, payment_id optional | E08, E09 | Учётные журналы FU/RB Core; source operations Cards/Loans со ссылкой на posting | Граница учётного факта; не смешивать с авторизацией карты | Повтор выгрузки, поздняя проводка, reversal как удаление, двойной импорт карточного и core-факта |
| E08 Проводка / Ledger Entry | entry_id, transaction_id, account_id, debit_credit, amount decimal, currency, book, posting_sequence | E07, E03 | FU/RB Core, соответствующий утверждённый subledger | Нужна для двойной записи и сверки остатков | Потеря одной ноги, неверный знак/масштаб, разные precision/rounding |
| E09 Платёж / Instruction | payment_id, external_reference, debtor/creditor refs, amount, currency, state, accepted/executed_at, idempotency_key | E03, E07 (0..N исполнений/учётных частей) | FU/RB Core или имеющийся payment module; ESB/каналы | Намерение и состояние исполнения отдельно от проводок | Один платёж представлен несколькими сообщениями, повтор исполнения, unknown outcome |
| E10 Продукт и версия | product_id, source_code, product_type, version, tariff_version, effective_from/to, selling_legal_entity | E06, E04, E12 | Каталоги FU/RB CRM/Core/Cards/Loans | Общий каталог для продаж и сопоставления портфеля | Совпадающее имя при разных условиях, разные коды/тарифы |
| E11 Обращение | case_id, customer_id/source_ref, channel, category, opened/closed_at, status, related_agreement_id, text_ref | E01, E06 optional | FU/RB CRM, контактный центр | Объединённая история обслуживания | Неоднозначный customer_ref, дубли, ПДн в свободном тексте |
| E12 Справочное значение | dictionary_id, code, version, label, effective_from/to, source_code_map, owner | E10 и атрибуты других сущностей | Все FU/RB системы; нет общей синхронизации | Единая трактовка статусов, отделений, сегментов | Разные значения одинакового кода, удаление используемого значения, устаревшая версия |
| E13 Согласие / разрешение цели | consent_id, customer_ref, purpose, legal_basis_ref, status, valid_from/to, revoked_at, evidence_ref | E01 | CRM/каналы; место хранения уточнить | Объединение данных не даёт автоматического права маркетинга | Нет доказательства/цели, отзыв не распространён, смешение оснований обработки |
| E14 Сторона договора | agreement_id, customer_id/source_ref, role, effective_from/to, evidence_ref | E01, E06 | Core/Loans, CRM ввод/использование | Совместный счёт, созаёмщик, поручитель, представитель; нельзя один FK считать всеми ролями | Потерянная роль, ошибочный owner после merge, временные пересечения |
| E15 Валютный курс | rate_date/time, base/quote_currency, rate_type, value decimal, provider, version, approved_at | E08/E09 при конвертации, аналитические факты | Утверждённый treasury/Core feed FU/RB; источник согласовать | Отчётность разных валют с воспроизводимой переоценкой | Разный rate type/date, округление, смешение transaction currency и reporting currency |

E02, E08, E13–E15 добавлены для трассировки, финансовой сверки и прав. Начальные «операция/транзакция» уточнены как E07+E08; «платёж» E09 оставлен отдельно. Документы представлены управляемыми ссылками с метаданными и версиями в объектном хранилище; отдельная предметная модель документооборота не нужна для поставленной задачи. Юрлицо банка и книга учёта — обязательные сквозные ключи, а не выводимые из названия бренда атрибуты.
