# FinUnion и RetailBank — архитектура данных после слияния

Sprint 6. Решение объединяет идентификацию клиентов и аналитические данные, сохраняя финансовый учёт в профильных банковских системах. Через три месяца предлагаются Customer Hub, матрица владельцев, контролируемые потоки и объединённая управленческая отчётность на PostgreSQL. Через год — MDM, DWH для отчётности, Lakehouse для истории и событий, каталог и управляемые data-продукты.

## Основные решения

- Единый `customer_id` связывает source IDs; спорное совпадение не объединяется автоматически. Merge/unmerge сохраняет историю и не меняет договорного владельца счёта или права доступа.
- MDM отвечает за идентичность и согласованные справочные атрибуты. АБС, карточные и кредитные системы остаются мастерами финансовых объектов; `legal_entity_id` не исчезает вследствие покупки банка.
- BI читает только аналитические хранилища. PostgreSQL DWH выпускает воспроизводимые сертифицированные отчётные версии, Lakehouse сохраняет большие исторические и событийные наборы.
- Миграция выполняется по наборам данных и потребителям. Отключение RB CRM/DWH/BI возможно после доказанной замены; RB Core/Cards/Loans не выключаются по одному календарному сроку.

## Факты, предложения и ограничения

Сроки **3 и 12 месяцев**, ограничения непрерывности, защиты и финансовой корректности заданы кейсом. Конкретные объёмы, СУБД АБС, throughput, SLA, RPO/RTO, бюджет и штат неизвестны. Численные показатели свежести и времени отчётной готовности ниже — предлагаемые SLO для согласования, а не измеренные факты или утверждённые SLA.

BIAN используется как словарь ответственности, не физическая ER-модель и не требование развернуть сервис на каждый домен. Для воспроизводимости выбран проверенный каталог **BIAN release 12.0.0**, а не заявлена поддержка самой новой версии.
